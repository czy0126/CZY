## 实际修复

1. UCC24624结温绝对上限由错误150°C改为125°C，150°C另列存储上限，不参与结温判断。
2. 95mA和13mA是12V及不同REG电压下的手册值；外推到15V的计算改标CONDITIONAL_SCENARIOS_NOT_15V_BOUNDS，撤回worst-case命名。实际板热阻未知，不再从JEDEC热阻表直接设定台架限流或批准保持时间。
3. 30mA保留为初始仪器设置，并明确不是安全电流保证；VDD跌落或PSU进入限流的波形不能用于证明稳压15V下的关断性能。旧“高温按表下调”可能把30mA升到32.7mA的建议已删除。
4. 新增 tools/check_reg_hold_capture.py，把“未启动的REG/本来就低的门极”与真实关断分开；它检查原始CSV，并记录输入文件哈希。测试内合成数据只用于单元测试，没有写成台架证据。

原厂核对：[TI UCC24624 Rev.C手册](https://www.ti.com/lit/ds/symlink/ucc24624.pdf)，第4页TJ/Tstg、第6页电流条件及REG/VD启动要求。REG与VDD是不同引脚；双路SR互锁，不要求同时导通。DeepSeek的这两处混淆已明确退回并在最终回复中纠正，过程见 deepseek/20261107_review/。

## H1检查的明确边界

输入采用同一时间轴CSV：

`t_s,fault_v,vdd_v,reg_v,vgs1_v,vgs2_v,vd1_v,vd2_v,bias_a,psu_cc`

- VDD测U1.7对PGND，REG测U1.3对PGND；VGS必须测实际栅源差，不能以驱动输出对PGND替代。VD1/VD2以VSS为参考。探头、仪器、板版本和偏置限流设置写入manifest。
- 至少10µs故障前记录：VDD为15V±5%、无PSU限流、REG已达到9.9V；两路门极各自曾连续≥0.2µs高于4V，至少一路在故障边沿前处于高电平，两路不能同时高。
- 从FAULT_IN上升到100µs保持结束，VDD和PSU状态持续满足条件。25µs后REG≤3.63V、两路VGS≤1V并保持；每个最多10µs检查窗内VD激励仍有两种极性，避免把停止驱动激励当成故障抑制成功。
- 时间严格递增，最大间隔0.1µs；重复时间、缺行间隙、NaN、记录不足均拒绝，不通过插值补出“通过”。一次异常不做平均消除。

以上为当前约200kHz低能量H1台架的工程筛选条件，不是芯片保证时序。采样通过仍不能排除带宽之外的尖峰；探头带宽、同步和原始文件来源必须人工复核。工具只输出WAVEFORM_CRITERIA_PASS_ONLY，不批准热、真实功率换流或硬件运行。没有用CSV自我声明取代来源审查。

使用模板：pcb/sr_fault_validation/h1_capture_manifest.template.json。复制为实际采集manifest后填写仪器及文件路径；不能把模板或测试合成波形改名当实测。

```powershell
python tools/check_reg_hold_capture.py <实际manifest.json> --output <检查结果.json>
```

当前对模板的实际检查结果为 **NOT_READY**，保存在 pcb/sr_fault_validation/h1_evidence_status.json；非零退出码是预期的缺证据状态。H0–H5全部executed=false，H5已明确标注“待实施ECO”。

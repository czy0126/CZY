# 40 — D1 5 A / 10 A SR_ON 原始 Windows 求解失稳与 RAW 证据

日期：2026-11-08。全部是 MODEL_DIAGNOSTIC_ONLY；未取得完整 5A/10A SR_ON 结果，更没有硬件验收。

## 真实证据

源：GitHub Actions 42476649133，官方下载的 ADI LTspice Windows 24.0.12。安装包签名检查通过，SHA256=62a9f20b630738e6ade20a37551baa91b20760bfb718807d8a2be4caa3421a36。

5A SR_ON: .log SHA256=ff20e6a3b183d2244ba29f8e2da2c864de76ab1510e7356d753bbca080818028；.raw SHA256=cb4cd811f4c8b1b846642bd1d536b0b33d20373b61aea43fd28b2f082e72abf2。约 0.5698 ms 时产生 Singular matrix: Check node d:sb4:bd#int1 并退出，未运行至 8 ms。第五至第七毫秒平均输出不存在。

10A SR_ON: .log SHA256=a30d4d06e0d435e3288cf9c1684b265e5ca63b9a5a5eb79a8b7e18506d8241e7；.raw SHA256=15af90654c4f08d05117bfe17a73ec2966bb4be23f8c2694fa0662512ef72fac。第一个非数值 RAW 点在 0.000557825653746 s（第三列波形）。虽仍记录至 8 ms，但后续多通道 NaN，统计输出等为 1e308 或 -1e308，这不是物理结果。

两工况在输入母线 0.4–0.8 ms 上升期出现异常，早于原网表的 REG 供电 1.2–1.4 ms。因此无法仅据 SR_ON 名称将故障归咎于正在工作的门极驱动；应先定位 MOS 二极管内部节点 d:sb4:bd#int1、负载初始条件和 solver 数值行为。

5A/10A SR_OFF 在上一轮因为先运行 ON 并提前异常退出，并未被独立求解；本次 runner 修改为 ON 失败后仍强制继续 OFF，同时保留失败事实。

## 直接修改和验收

- tools/run_poc_low_current.py: 能读取 Windows UTF-16LE / UTF-8 日志，拒绝数值哨兵大于等于 1e100；不再让 ON 失败掩盖 OFF 结果；即使只有 OFF 成功也保留真实数据并返回非零状态。
- tools/poc_raw_evidence.py: 逐点扫描标准 LTspice 原始 .raw，严格校验 Header 点数、字节长度、每个 float 的有限性、时间单调性和完整 8ms 末端。拒绝非支持的二进制布局，绝不把 0.56ms 后全 NaN 的 8ms 文件视为完整仿真。
- 模型库 models/sr_device_v3.lib 未被篡改；所有修改只是证据验证与运行控制，不会伪造新的工作点。

## 下一步实验

1. 独立执行 SR_OFF 5A/10A，判断是与 SR 控制无关的 SR_DEVICE 二极管/非线性寄生造成的模型问题，还是仅 ON 拓扑。
2. 保留黄金版参数，另建不可冒充基线的诊断副本，缩短到 0.62ms 并依次尝试仅改变数值求解器、临时关闭模型二极管反向恢复、增加弱漏电路径。每次以 raw finite/time/回路应力来区分数值稳定与真实性，成功的简化版本绝不能取代原模型给出效率数据。
3. 原生 EasyEDA R8 ECO、磁件 DOT/端子、D0 真栅极关断、SR 持续反灌及 100A PCB 仍是完全独立的硬件前置条件；模型预检不授权制造或通电。

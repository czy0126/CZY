# 第21章：50V保护设计决策——A组可配对但对峰值无效，先补B组2fF

这份决策从**已提交的JSON**逐次重算，不声称在本轮运行新的LTspice：`python tools/prot03_50v_evidence_decision.py --check`；结论和数值存于 [可追溯决策JSON](../../design/v3/power_priority/prot03_50v_protection_evidence_decision.json)。

## A组：2fF两侧均320µs、故障前0mV偏差，但不减少初始峰值

- 保护A在 215.023151µs 才触发；同数值辅助条件下对照的原边峰值出现在 209.94941µs，峰值已过去 **5.073741µs**。
- I(Lr)峰在控制和候选均为 **101.069A**；单只SR最大正向峰均 **303.411A**；八SR正向I²t总量只减少 **0.676%**。
- 因此A组可以用于逻辑锁存/保护接口诊断，但**不能按当前阈值与监测时序作为保护高峰值的最终方案**，也不能因为“七项检查全绿”就判为硬件安全。

## B组：1fF旧数据有明显削峰潜力，但严格对照仍不完整

- 1fF行为模型B组候选达到320µs、对照仅到**254.980482µs**；旧报告给出的SR峰值相对下降约 **54.312%**，只是**被截断对照上的仿真改善提示**，不能写成完整故障窗口的定论。
- 必须在同一个2fF参数下完整运行B_CONTROL、B_CANDIDATE，保证双方320µs与140–175µs故障前Vout差≤1mV，并记录8SR与原边门极；即使通过也仍是0.05Ω行为级钳位模型。

# Fast preflight: ADI LTspice 26 true -b batch 1V smoke (2026-11-08)

Original ADI LTspice 26 Windows #42480573709 0.62ms root-cause matrix had **all four** modes (SR_OFF, SR_ON, TT=0 and weak leakage) time out at 840 seconds, with **no .log/.raw in artifacts**. This is different from LTspice24 circuits that wrote .raw/.log and had genuine ~0.56ms numerical failure. Since even SR_OFF with TT and weak shunt changes cannot produce a log, **do not infer an SR diode defect solely from the LTspice26 no-evidence timeout**.

An official Windows LTspice -b batch interface is documented by ADI, but a fresh installation may have user-interface initialization or consent handling on first launch. The exact reason is **not verified**, so this PR adds `tools/ltspice_batch_smoke.py`, a tiny independent .cir: 1V source, 1k resistor and .tran 2us. It enforces nonempty real .log/.raw, finite 1V .meas, complete 2us RAW, SHA256 and 25s timeout. If it hangs, the entire D1 run stops before wasting ~15-30 minutes. It will not click GUI dialogs or consent on behalf of the user, and **will not report an unperformed simulation as success**.

Output: `sim/v3/_ltspice_batch_smoke.{cir,log,raw,json}` in the Actions artifact, with explicit `BATCH_SMOKE_PASSED_NOT_D1_EVIDENCE` vs `BATCH_SMOKE_STALLED_BEFORE_VALID_EVIDENCE`. No test touches the original D1 power-stage netlists.

Next steps: if 1V trivial smoke fails, fix Windows runner's LTspice initialization or use a properly initialized licensed desktop Windows workstation to rerun the same official tool. If 1V passes, only then spend CPU diagnosing 5A and 10A startup. Either way, the D0 hardware gate and native PCB fabrication signoff remain separate.

Reference ADI documented -b: https://github.com/analogdevicesinc/ltspice-reference/blob/main/ai_ref/LTSPICE-QUICKSTART.md

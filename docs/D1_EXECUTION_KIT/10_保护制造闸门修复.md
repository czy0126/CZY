# P0 修复：保护设计审查成为独立制造门槛

旧的 d1_fabrication_gate.py 即使将来黄金网表/ERC/PCB/制造资料全部齐全，也没有独立检查故障时主桥+八只SR默认关断是否有**真实物理电路**。当前已知的理想锁存钳位只有仿真，不应独自构成放行依据。现新增独立的 **independent_fault_shutdown_design_evidence** 检查，未收到工程审查证据始终 NOT_FOR_FAB。

## 怎么解锁这项，不能靠填 true

1. 完成真实硬件关断原理图：UCC25600 和原边驱动禁能，四组 8 SR 全部失压下拉；设计必须解决是否可直接钳位 UCC24624 推挽输出的器件输出级争用问题。
2. 保存完成且 GUI 可重开的 hardware/dcx_main/dcx_main_board.eprj2，记录文件 SHA256；必要时附分离的保护电路审查报告、驱动/供电时序、厂家真实 SOA 原件。
3. 逐项审查：启动屏蔽期间故障、故障锁存和安全重启、任一偏置丢失默认禁能、主桥+8SR 的逻辑/电力连接、真实门极驱动关断器件、厂家脉冲 SOA 与磁件峰值。
4. 48/50 V、至少 120 A 对照仿真覆盖每只 SR Vgs/Vds/Id；50V 基座停算、保护候选非配对记录不能直接标为通过。
5. 由独立工程师签名、填写 hardware/dcx_main/protection_design_approved.json 中每项及五份源文件的 SHA256。可复制 protection_design_approval_TEMPLATE.json 填写，但模板本身不算获批文件。
6. 运行 python tools/d1_fabrication_gate.py --write 和 python tools/d1_fabrication_gate.py --require-release。即使保护签核通过，磁件真实脚号、占位、ERC/PCB/制造包任一缺失仍不得投板。

此门槛检查的是文件存在、哈希、参数覆盖及审核布尔字段，**不能自动判读电路是否真安全**。实际工程签核仍需人审和首件实测，功率/热连续额定仍独立禁用。

复测：python -m pytest tools/test_d1_fabrication_gate.py -q；python tools/ci_check.py。

# 第19章：冷启动也必须有效的双层独立硬件保护

此前PROT-B的1.8V/10µs滤波快速检测不做`arm`会在启动过程提前锁死；只在`SS>4.8V`后允许快检测，又留下冷启动短路期间的不受保护窗口。**解决方法不是全部屏蔽，而是区分两类保护：永久有效的硬过流保护+可在软启动后使能的快速敏感保护**。当前只固定逻辑需求，不凭历史波形臆定最终CT门槛。

## 原厂检测器件

[TI TLV3211DCKR](https://www.ti.com/product/TLV3211/part-details/TLV3211DCKR)是确切可查询的SC70-5高速比较器候选：供电1.8–5.5V、典型传播40ns、带Power-on Reset，低压启动时输出保持LOW，适合将比较器信号定义为`HARD_OK`（LOW为无效/故障）做默认禁止。该芯片**不能直接接12V、也不能直接承受未经限压的CT负载脉冲**；必须先定义CT输出整流、分压、滤波、钳位与偏置欠压，按最坏输入幅度选择精密基准和限流电阻。单靠一个TLV3211并不能实现系统两路故障检测、独立锁存、自动故障复位阻止。

## 逻辑架构

- `HARD_TRIP`：硬件比较器、CT断线/短路诊断与偏置失压检测，任何时刻均有权禁止所有10路门极。包含实际硬件Latch，**不经过SS mask**。
- `FAST_TRIP`：低噪声高灵敏度快速保护，可在可靠软启动后使能。启动期间FAST_TRIP即使被屏蔽，HARD_TRIP不得屏蔽。
- `FAULT_LATCH`：上电初态必须硬件置位。任何硬故障、已armed快故障、任一偏置/CT检查失效立即锁存；故障解除不自动恢复。只有全部10路门极确认为低、所有偏置/CT信号有效、启动顺序就绪，并且在故障后确认复位键曾在健康状态下**释放为低**、再收到**一次新的上升沿**时才允许复位。连续按住的复位键绝不能在故障清除、上电恢复后自动解锁。实际硬件需证明断电再来不会留下“未锁存的默认开通”瞬态。
- 原边R8永久1k上拉禁止真实硬件失压停机，需DNP；NCP4306 B方案需要TRIG/DIS默认HIGH本地上拉，双路许可都健康才被拉低使能，不能和UCC27524A的默认LOW EN混淆。若原副边地有隔离边界，不能直接传递5V/12V许可，需域隔离。

新增 [`tools/two_tier_fault_logic.py`](../../tools/two_tier_fault_logic.py)及自动测试，穷举11个布尔输入、前一锁存状态、复位键上次电平和健康释放资格（16384组条件），任何一项`hard_trip`、CT无效、比较器或两路偏置失效都必须同时关闭原边和全部8只SR。另有上电、复位键按住跨越故障/断电、启动被屏蔽、故障后的人工复位、SR未关门就复位等14例JSON：[真值表](../../design/v3/power_priority/two_tier_fault_truth_table.json)。所有结果均为**纯逻辑，没有真实传播时延和电路供电/寄生模型**。

## 真正施工的顺序

1. 先画5V比较器电路：CT实际波形最大/最小值、整流极性、隔离/钳位、快/硬阈值裕量与比较器反相输入；优先保留原UCC25600的过流检测独立于这条链。未计算齐输入界限不决定比较器阈值。
2. 再选实际复位优先、故障置位优先锁存器/晶体管互锁和上电默认失效安全，确保真实偏置全部掉电又恢复时不自动启机。不能仅把Python状态机称作离散硬件。
3. 先做限能控制板，注入DC低/高故障和电源丢失测试，再接栅极电容等效负载，最后接原LLC高电流功率级。执行 [`18种故障测试矩阵`](templates/protection_hardware_fault_matrix_18.csv)和独立的完整冷启动短路工况。

## 2026-11-03 复位安全审计修补

原抽象 `transition(latched_off, inputs)` 将 `reset_ack=True` 视为有效的复位电平，因此**故障期间一直按住复位键**，等故障信号自行消失后，可能在无需新动作的情况下解除锁存。新版新增 `ResetMemory` 两个状态：`reset_ack_was_high` 与 `ack_low_seen_while_healthy`；先在健康状态下确认复位键松开为低，随后必须出现新的ACK上升沿才可复位。断电/故障会清掉松开资格，故障时SET始终压过ACK。自动测试覆盖保持高电平跨越电源恢复、故障期间按住及全部16,384组静态状态输入。**这仍是抽象模型；真实硬件需要带POR的复位资格锁存、按键去抖、Set优先关断链及独立测试，不能把Python模拟当作已经实现。**

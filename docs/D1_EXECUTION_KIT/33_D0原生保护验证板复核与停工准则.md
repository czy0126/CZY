# 33 · D0 保护验证板：实体脚号与模拟安全限制（2026-11-05）

**对象**：`tools/make_d0_protection_board.py` 自动生成的 `pcb/d0_protection/` KiCad 原理图、网表、BOM 与逻辑测试；同时复核 D1 主功率板下一步方案。

**当前决策：不能投保护板，也不能投主功率板。** 原因不是 KiCad ERC，而是独立电气/模拟证据不足。新增的静态审计与修复**不产生真实 PCB 和保护等级认证**。仓库未提交 `pcb/d0_protection/*.kicad_pcb`，只有可编辑原理图、BOM 和导出网表，不能叫“保护样板已完成制造”。

## 1. 已直接修复：U2（TL431LP）实际封装

新 D0 生成器中 U2 原为 `Reference_Voltage:TL431LP`、`value=TL431LP`，但**实例封装被指定 `Package_TO_SOT_SMD:SOT-23`**。这与 TI TL431 **LP = TO-92** 的实物封装不一致；TI TL431 **DBZ = SOT-23-3** 才使用 SOT-23，而且引脚顺序不同。

已把**生成器**、原生 `.kicad_sch` 中的 U2 实例、`BOM.csv` 和导出 `.net` 中的 U2 改为 `Package_TO_SOT_THT:TO-92_Inline`，无其它外围器件脚号修改。特别注意：**TI LP 实际脚号：1=K、2=A、3=REF；KiCad 内置 TL431LP 符号将 1/3 的文本名称反写。** 本电路 pin1 和 pin3 **均固定接 REF_2V5**、pin2接地，所以其功能目前恰好等效；如果未来改为可调参考、K与REF分开，就必须重新制作经过 OEM 核对的正确符号，**不能继续使用这份内置 pin name 作为物理脚号来源**。

交叉回归：`python -m pytest tools/test_d0_oem_package_mapping.py -q`。

原厂依据：[TI TL431/TL432 Rev. S §5 封装与管脚表](https://www.ti.com/lit/ds/symlink/tl431.pdf)。

## 1.1 本轮新增直接修复：U13 HEF4093BT 封装与实体 BOM 重复计数

- **HEF4093BT 实物封装是 Nexperia SO14 (SOT108-1)**，不是 DIP14。原生 D0 生成器之前在 U13 的 **五个逻辑单元**均使用了 `Package_DIP:DIP-14_W7.62mm`。现对生成器、真正原生 `.kicad_sch` 五处实例、嵌入式符号默认封装、原生导出 `.net`、已提交 BOM 同步改为 `Package_SO:SOIC-14_3.9x8.7mm_P1.27mm`。这是另一个 ERC 可能无法识别的**器件与物理封装不匹配**。证据：[Nexperia HEF4093B Rev. 11 (2024-09-05), Table 1 SO14](https://assets.nexperia.com/documents/data-sheet/HEF4093B.pdf)，当前采购拟购料号 `HEF4093BT` 仍须核对具体厂家订货后缀、实际装配图和焊盘间距。
- 旧 `pcb/d0_protection/BOM.csv` 有 **214行**但仅 **176个不重复的真实位号**。U3–U13 由 KiCad 多单元符号表示一颗真实芯片，原来按单元输出 U11 等多行会误导采购数量。已将生成器 `physical_components()` 实体去重：**176 个真实装配器件位号，逐个 Qty=1**；217 个符号实例仍完整保留，其中3个为不采购的电源 `#FLG`。报告 `physical_parts` 已由214纠正为176。
- 新增 `tools/test_d0_physical_bom.py`：对生成器、已提交 BOM、原生原理图及导出网表逐项核对，确保 U3–U13 仍有全部逻辑单元但每颗实体IC只出现一行；不同单元若出现不同的封装/器件型号/装配状态/数据来源立即拒绝，而不是默默采用一行。**BOM位号正确并不等于已选物料均获得厂商型号与量产许可**：D0仍无真实PCB、实体试验与器件SOA签核。

## 2.1 整改（2026-11-05）：最大值检测取代求和，比例分压取代齐纳

**P0-1 单路残压。** 十只 `BAT54` 各串在自己的 1k 支路上，阳极接门极、阴极共 `GSMAX`；只有**最高**的那一路正向导通，其余九路反偏、对上拉节点不贡献——所以关断的九路不再能把它拉下去。单路 3 V 读 **0.637 V = 3.2 倍参考**（旧 10k 求和是 **0.150 V**，参考 0.200 V，即“全关”）。门限 **0.9419 V** 的理想二极管值 + Vf；十路全高时节点是被**拉高**的，不是被稀释的。**它说不了是哪一路**：一只二极管或 1k 开路会盲掉一路，而全高测试照样读到 2.629 V，所以 `gate_sense_bring_up()` 给出逐路首件判据（十路各驱动一次，每路都应读到 2.123 V）。

**P0-2 低电流齐纳。** `D9 BZX84C3V0` 已删。`R76 22k / R77 6.2k` 的分压上限是**电阻比**，与流过多少电流无关：`GATE_SENSE ≤ Vgate × 6.2/28.3`，12 V 时 2.629 V、15 V TVS 钳位时 3.286 V，都在 LM393 的 `VCC−1.5 = 3.5 V` 内；反算门极轨上界 **15.976 V**。Vf 只会让节点更低，所以这个上界对任何二极管压降都成立——这正是齐纳给不了的。

**P0-3 “更快”不等于“更灵敏”。** 两个门限不在同一个节点：`V(ocdf)` 直接在 burden 上（增益 1.0），`OC` 在 `Rf/Rd1/Rd2` 分压之后（增益 **24/35 = 0.6857**）。按各自节点换算，快门限 **29.39 A**、硬门限 **24.23 A**；实测（`design/v3/stage_f/d0_trip_timing.json`）快通道在故障后 **10.21 µs** 翻转、硬通道 **40.10 µs**，即**早 29.88 µs**。所以“更快”成立、“更灵敏”不成立，两句话必须分开写。

**仍未关闭（`status` 保持 `ANALOG_SAFETY_NOT_QUALIFIED`）：**

- 逐只 MOSFET 在最差温度/器件差下的**安全关断 VGS 门限没有被写下来**。检测器只报告“某路门极在约 1 V 以上”，不等于“该管已关断”。
- `BAT54` 的 Vf 随温度与批次变化，仓库里没有它的 datasheet。理想门限 0.9419 V 到 SR 的 `VGS(th)` 下限 1.3 V 之间只剩 0.36 V，按 0.3 V 压降占位只剩 **0.058 V**——这一条必须首件实测。
- LM393 的 **3.5 V 共模上限仍是沿用假设**，仓库没有 LM393 datasheet；它现在只影响“上界够不够宽”，不再影响“钳位会不会失效”。
- 隔离电源欠压、共同地回路、POR 顺序、比较器/驱动器传播延迟，仍需 §3 的台架记录。

对应回归：`tools/test_make_d0_protection_board.py`（检测器算术、每路一只二极管、共模上界、十步首件扫描）与 `tools/test_d0_analog_preflight.py`（整改后的残余项必须仍列为未验证）。

## 3. 下一阶段真正能改变“未认证”的工程交付

**P0-A：完成保护板原理图的安全整改（优先于画PCB）。** ✅ 2026-11-05 已实施，残余项见 §2.1；下面这段保留为原始要求。不建议把汇总GSUM直接当“全部十路可靠关断”。优先选择10路彼此独立的VGS阈值检测并作硬件与关系，按 MOSFET 在最差VGS/温度/器差下的关断边界确定门限，考虑比较器偏差、RC延迟、源极 Kelvin 引线和输出驱动失压；如果保留GSUM，必须以故障注入和 OEM 最差参数证明覆盖每一路。D9的钳位应改为在**实际可供电流/温度**下有确定上界的结构，不得使用 BZX84 标称点外推。隔离电源欠压、共同地回路和芯片 POR 必须在电路中核实，不得只由软件逻辑测试代替。

**P0-B：再建立真实 PCB。** 将本目录原生 `.kicad_sch` 导入 KiCad PCB，冻结含真实 MPN/制造封装/完整焊盘号的 BOM；核对每个 comparator、电源监管、driver 与逻辑门每一个物理焊盘。完成布局铜箔、探针地回路、输入偏置限流、ERC/DRC/间距/绝缘与厂家层叠审核。**没有 `.kicad_pcb` 就不把生成原理图称作实体 PCB**。

**P0-C：低能量实物验证。** 用隔离、限压限流电源和全部10路假电容负载，逐条执行[18例硬件故障矩阵](templates/protection_hardware_fault_matrix_18.csv)：硬故障、软启动短路、ACK常高、CT开短路、偏置UVLO、POR先后上电、每路门极失能、门极与使能线短路等。记录实际故障物理注入源、触发时刻、10路 VGS 和电源/复位波形；跨仪器对齐请按[31/32章](31_D0多仪器同步对齐与重采样.md)完成，绝不凭软件合成CSV勾选通过。

**P0-D：主功率板并行。** 主板 `hardware/dcx_main/dcx_main_board.eprj2` 中 R8 的常上拉尚未做真实 ECO；旧主板83位号、61占位器件、T1–T4/CT厂家24个真实焊盘与DOT、GUI ERC、有网PCB仍阻塞制造。完成这些文件及真实实测后，才进入D1 48V/100A级≤16mm的低压→25/50/75/100A阶梯调试；120A与≤10mm是后续D2、D3，不要把机械≤10mm强行作为D0开板阻塞。

## 4. 严格停止条件

1. **通过 KiCad ERC** 只代表软件原理图没有相应语法/连接违规，不能越过模拟钳位、片内延迟和实物验证。
2. **仅匹配软件逻辑状态机** 不算复现 POR、比较器缓慢跨阈值、时钟抖动与源极振铃。
3. **报告中的 `ANALOG_SAFETY_NOT_QUALIFIED`** 必须保持到有可核实、可复算的方案级整改和台架测试，不可由人工把布尔字段手改为true。
4. **完整保护样板并非功率级投板许可**；制造闸门继续 `NOT_FOR_FAB`，器件SOA、磁件L(I)/DOT、热设计、铜损须独立满足各自关卡。

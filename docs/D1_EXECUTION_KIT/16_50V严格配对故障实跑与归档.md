# PROT-03：50V严格配对实跑与原始数据留档

当前 **未解决** 的技术事实：A/B行为保护候选分别有完整320µs记录，配对的`thrmute`控制虽在故障前140–175µs窗口Vout差值为0mV，却分别停在250.151和254.980µs。此前调节`Vt=10`的无钳位控制完成320µs，但比候选的故障前Vout有13.2/17.5mV偏差，不能满足1mV同工作点配对条件。

新增 `tools/run_d1_50v_matched_cases.ps1` 以**真实存在的四份原始deck**为输入，不生成新电路。默认只检查是否可运行，只有显式`-Execute`才启动本地ADI LTspice。它将拷贝保存在同一个`sim/v3`目录的唯一命名deck，从而保持`../../models`引用不变；完成后把输入、完整或提前结束的RAW、LOG移至`out/d1_50v/<RunId>/<CASE>/`，并将SHA256、结束时间、状态写入`run_manifest.json`。同一RunId不能覆盖。

```powershell
pwsh -File tools/run_d1_50v_matched_cases.ps1
pwsh -File tools/run_d1_50v_matched_cases.ps1 -Execute -RunId d1_50v_001 -LTspice 'C:\Program Files\ADI\LTspice\LTspice.exe'
```

先只重跑B组时可用 `-Cases B_CONTROL,B_CANDIDATE`；PowerShell脚本仍只在显式执行后运行。安装位置若是用户目录，则可省略`-LTspice`由脚本搜索常见位置；没有LTspice时会拒绝执行。ADI原厂[LTspice命令行快速参考](https://analogdevicesinc.github.io/ltspice-reference/ai_ref/LTSPICE-QUICKSTART.html)列出`-b`和`-ascii`。后者使RAW能被仓库`ascii_raw_window.py`读取，但明显增加运行与存储负担。

**通过标准**必须同时满足：A、B各自完整320µs两份RAW和日志；故障前140–175µs Vout均值差≤1mV；只变动保护触发阈值、不改功率回路及器件温度模型；逐只记录8只SR及2只原边Vgs/Vds/Id、独立保护信号、SOA和失压时序。`run_manifest.json`的`DURATION_ONLY_PASS`只表示完整保存轴，不会自动标记配对或实物安全合格。

对于得到的新RAW，使用已有 `tools/protection_candidate_compare.py --case ... --base-raw ... --candidate-raw ... --base-deck ... --candidate-deck ... --json ...` **另存**新的版本化分析JSON，不覆盖主分支现有已发布历史波形。如果控制再次卡住，先检查故障后死区的浮动门极、电容电流、求解器步长；任何收敛选项（包括cshunt）必须对候选与控制成对修改并另建比较变体，不能混用。

**本轮没有执行LTspice、没有取得新RAW。** 当前旧行为钳位不等价于 [15 真正的硬件门极禁止方案](15_十路硬件故障关断接口及实施验收.md)，后者还需要实际TI驱动模型、真实电路与硬件试验。

# 第30章：T1–T4 / CT 共24个物理端子回件自动审查

> **实际交付：代码、严格模板、自动反例测试。没有原厂真实端子图、L(I)、实物极性试验、GUI ERC或PCB；仍 NOT_FOR_FAB。**

## 1. 解决什么问题

当前 `magnetics_symbol_contract.json` 已有5只磁件的逻辑引脚、黄金网名和模型DOT，但**所有 `physical_pad=null`**。把逻辑 `PRI_A/SEC_A/CTAP` 直接复制到厂家的实体焊盘编号，或者根据模型 DOT 反推未知 CT 绕向，会造成错误但可能通过逻辑网表比较。真实可投制的绘图必须来自供应商的物理端子图，再经过独立低能量相位验收。变压器的DOT表达耦合绕组相对极性，不能只把数字焊盘位置视作极性依据；参见 [TI SNVA559 变压器基础](https://www.ti.com/lit/an/snva559c/snva559c.pdf)。

本轮新增 `tools/magnetic_vendor_map_audit.py`：对供应商回件逐项执行24个端子的集合检查、每只磁件实体焊盘去重、源黄金网络与模型DOT冻结、厂图修订、真实封装替换字段、XY 坐标、资料 SHA-256 格式和低能量极性试验记录完整性检查；**同一只磁件的全部端子必须共享同一个 `mechanical_footprint_ref`、`manufacturer_drawing`/`drawing_rev`/`drawing_sha256` 与 `phase_test_record`/`phase_test_sha256`**（哈希比较不区分大小写），否则回件被判 `CONTRACT_REJECTED`——每行都填满不等于它是一只能被审查的零件。原有9行 `magnetic_terminal_map.csv` 只作早期历史模板，**不得作为24端完整回件**。

报告同时记录回件与合同两边的 SHA-256：`input_sha256` 是供应商 CSV 的字节散列，`contract.sha256` 是判定时所依据的 `hardware/dcx_main/magnetics_symbol_contract.json` 的字节散列（附 `symbols=5`、`logical_terminal_count=24`）。**审核结论只对这一对字节成立**：合同一旦被修改（例如向 `physical_pad` 写入真实焊盘后重生成），旧报告即失效，必须重跑审核；把旧 JSON 带进制造资料包等于用旧版黄金网/极性判定新回件。合同自身若出现重复逻辑端，工具直接报错退出（`INVALID_PACKET`），不允许字典合并悄悄把期望端子从24个缩水。

## 2. 供应商应填写的正确表

以 [24端子回件模板](templates/magnetic_vendor_response_24_TEMPLATE.csv) 为唯一输入格式，从 `hardware/dcx_main/magnetics_symbol_contract.json` 自动推导24个逻辑位号与电气网；初始全是 `PENDING`，不会意外通过。

关键列：`supplier_terminal` 是厂家实体焊盘编号，不能填 `PRI_A` 等逻辑端名；`supplier_dot` 每个原、副边端子需填 `DOT` / `NON_DOT`；每个主变 `CTAP` 只能填 `CTAP_SPLICE`，明确为两半次级反向参考端连接，而不是一个简单单向DOT。CT一次与二次端子各一DOT/一非DOT，**这只能验证内部标记自洽，不能证明CT方向与整机过流极性正确**。

`pad_xy_mm` 格式为 `x,y`，填真实图纸坐标；`mechanical_footprint_ref` 为厂家最终实装封装名，禁止照抄历史占位封装；`manufacturer_drawing`、`drawing_rev`、`drawing_sha256` 锁定厂家文件的真实版本。 `measured_phase=MATCH`、`phase_test_record`、`phase_test_sha256` 代表**首件低压实测记录**，`reviewer` 需明确审核人。统一状态 `SUPPLIER_PROPOSED` 仅表示供应商已提交，**不代表工程签核**。

**必须先有实体图、真实首样及记录，才能真实填写上述内容。** 不得直接把测试代码里的假料号/假哈希用于任何真实回件。

## 3. 使用方法

```powershell
# 在新路径生成一次全PENDING的供应商表，不会覆盖已有数据
python tools/magnetic_vendor_map_audit.py --write-template out/vendor_reply_24.csv

# 将厂家回信、独立极性和图纸信息填写到同一24行模板后
python tools/magnetic_vendor_map_audit.py --input out/vendor_reply_24.csv --output out/vendor_reply_audit.json

# 回归与独立制造闸门
python -m pytest tools/test_magnetic_vendor_map_audit.py -q
python tools/d1_fabrication_gate.py --require-release
```

结果：`INCOMPLETE_VENDOR_PACKET` 返回码1（还有待填资料）；`CONTRACT_REJECTED` 或 `INVALID_PACKET` 返回2（明显错误：缺漏、重复实体焊盘、网名/相位冲突、同一磁件端子身份不一致、错误CSV等）；`REVIEW_PACKAGE_COMPLETE_NOT_APPROVED` 返回0，**仅是可以交给独立设计审查的完整资料包**，不是任何电气、物理、绝缘、器件或制造许可。复核旧报告时，先比对报告里的 `contract.sha256` 与当前合同文件的 SHA-256：不相等就是旧版判定，不能沿用。

审查器的 `ct_relative_phase_independently_proven`、`supplier_document_authenticity_verified`、`physical_pad_map_verified`、`native_cad_replaced_with_real_footprints` 和 `fabrication_approved` **永远是false**；技术责任人必须人工核对原厂图纸原文、1:1焊盘、T1–T4中心抽头与CT极性，在真实原生EDA修改后导出全网表、ERC/DRC、做首件低压极性与绝缘试验，不能用本工具自动改 `.eprj2` 的厂家实际管脚。

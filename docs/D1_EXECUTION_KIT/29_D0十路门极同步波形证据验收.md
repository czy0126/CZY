# 第29章 · D0 十路门极同步波形审查工具（真实台架输入协议）

> **状态：可执行的软件审查工具，尚无真实台架测量。** 本章交付 `tools/d0_gate_capture_audit.py`、负向测试和两份原始数据模板，能够拒绝丢通道、未真正激励、晚于时限关断及关断后再次拉高；不能据此宣布 D0 已实物验收、器件 SOA 合格或 D1 能制造。

## 一、为何需要它

[第15章](15_十路硬件故障关断接口及实施验收.md)只锁定**候选保护引脚**；[第19章](19_冷启动永不屏蔽硬过流与自动化测试.md)的11输入真值表只是**软件布尔状态机**；[第26章](26_B组2fF软轨配对跑满320us与逐位比对.md)是行为源数值比较。以上均**未量测 UCC27282 原边 HO/LO 和八只 SR 的实际门源电压**。若只观察锁存器或 EN 输出，高栅压可能因驱动器延迟、供电地弹、寄生 Miller 注入、某一路 EN 错接或失压失效而残留，仍会被错误判为已关断。

本工具为下一阶段的 **D0 低能量十路电容假门极负载**提供独立时序检查。使用 [TI UCC27524A Rev.C](https://www.ti.com/lit/ds/symlink/ucc27524a.pdf) 的明确功能行为作为候选架构背景：其 ENA/ENB 悬空默认使能，只有低电平明确禁止输出。这证明必须实测每一路真实栅压，不能从通用许可线推导“十路已关断”。

## 二、采集要求（硬条件）

**只适用于**一次外部故障激励、之前十路都能被独立激励到可观察高态、故障后持续请求关断并保持观察窗口的 **D0 单次事件**。故障发生在冷启动、某通道未曾开通、断电缺时钟、断线等其它情况必须另外编写适用协议；**不能为了让本工具 PASS 在台架强行开通本不该开通的门极**。

- 先用**独立 SELV 限流、非功率级**试验：十路分别接对目标 MOS 管等效电荷有依据的电容/电阻假负载，尽量在门极/源极 Kelvin 参考处量 VGS，不要只采 EN、TRIG、UCC24624 VG、许可布尔量。
- 12 列（1列统一时间 + 1列**实际注入端的故障激励** `TRIP_STIMULUS` + 2个原边负载 VGS + 8个 SR 负载 VGS）必须**共享同一个时间基准**。若用多台示波器需先证明同步精度并在另一个经审核的重采样工具中处理；本程序不会也不应猜测时轴偏差。
- 十路波形列统一命名：`P_HO`, `P_LO`, `SR1A`, `SR1B`, `SR2A`, `SR2B`, `SR3A`, `SR3B`, `SR4A`, `SR4B`。**它们是每路实际VGS (V)，不是控制输入和门极电源。**
- `TRIP_STIMULUS` 为试验者**主动施加在保护检测链起点的物理故障激励**，从低→高并在其后持续有效。若采的是比较器/锁存器的故障输出，本工具计算的延迟**不包括传感与比较器延迟**，不得用于完整故障限流时间；记录触发位置、探头、电缆和对齐延迟。
- `time_s` 单位秒，严格递增，所有值有限且无空样；不能拿不同run的十路门极随意横向拼成同步数据，也不能用低采样率曲线掩盖短暂重新开通。
- 预故障采样长度需由真实开关周期与协议确定，**十路各至少一次到达审查设定的 `gate_on_min_v`**；检测窗口须覆盖最大允许关断时间之后的独立保持时间。正常LLC上下管互锁，**无须同时高**，也不能允许上下管同时高。
- `max_sample_spacing_s` 必须小于等于 `max_disable_latency_s/5`；这只是最基本的数字分辨率判据，纳秒级再导通仍需要足够带宽和探头，软件无法证明样点之间没有毛刺。

## 三、模板、参数与运行

- [配置模板](templates/d0_ten_gate_capture_config_TEMPLATE.json) 的延迟/门极/门槛全部是 `null`，`limits_review_status=PENDING`。**必须由电气与器件 SOA 审核后填写**，不能套用别的项目的通用 `1.0V` 或 `1.5µs`。
- [CSV列头模板](templates/d0_ten_gate_capture_HEADER.csv) 只有列头、零条波形。不能把它当实测数据或作为通过记录。
- `hardware_revision`、`instrument_id`、`limit_basis` 必须填写实际版本、设备序列/设置及已审核的时限来源；最后设 `limits_review_status=ENGINEER_REVIEWED` 才允许工具输出 `PASS_CAPTURE_ONLY`。填写这些元数据**不是**真实认证签字。
- 数据可以归档在仓库外 `out/d0_scope/` 下（Git 不存真实大波形），但是正式评审请保存原始示波器工程、CSV、探头校准、带宽、采样率、仪器序列、数据 SHA-256 和该报告。避免 CSV 二次导出丢失峰值。

示例（必须先用真实数据复制并填写，不可直接运行空模板）：

```powershell
Copy-Item docs/D1_EXECUTION_KIT/templates/d0_ten_gate_capture_config_TEMPLATE.json out/d0_scope/limits.json
# 在 out/d0_scope/limits.json 填写真实电气门槛、设备、依据和版本
# 将同一次同步采集按模板列序整理为 out/d0_scope/shot01.csv
python tools/d0_gate_capture_audit.py --csv out/d0_scope/shot01.csv --config out/d0_scope/limits.json --output out/d0_scope/shot01_audit.json
python -m pytest tools/test_d0_gate_capture_audit.py -q
python tools/d1_fabrication_gate.py --require-release  # 无其它实物证据时必须拒绝制造
```

**退出码：** `0` 为仅本次已审核限值下、CSV数字波形**通过采样检验**；`1` 为在有效采样下**不满足波形要求或元数据待审**；`2` 为**无效证据**（缺通道、时间不连续、NaN、阈值不合理、窗长不足等）。只要缺一个门极、任何门极没在故障前实际活动、任何门极晚关断或在截止之后再次高，就不得给出 PASS。

## 四、明确能力边界与后续真实试验

输出中的 `waveform_origin_authenticated=false`、`all_ten_real_hardware_gates_verified=false`、`hardware_protection_approved=false`、`power_stage_fabrication_approved=false` 是有意**永不自动升级**的。工具无法判别用户提供的是仿真 CSV 还是示波器数据；无法确认探头是否接在正确器件；也不计算 MOSFET 真实的第三象限 SOA、源极 Kelvin 偏差、功率级电感失效时的峰值/储能。

**不能覆盖的 P0 情况：** CT 原/副边开路、软启动时硬短路、12V/5V 偏置丢失、任一 EN 被短到 VDD、硬故障后 ACK 持续卡高、外部关断失败时 Miller/寄生重开通等。按照[18例故障矩阵](templates/protection_hardware_fault_matrix_18.csv)逐项独立制定试验并留下证据，部分场景必须检验门极持续低态而不是强求预先开通过；不能给该基础程序传入假的十路先行高态后冒称完成故障矩阵。

**当前最优后续路线：** 先制作真正的十路低能量保护电路（[Issue #36](https://github.com/czy0126/CZY/issues/36)）；原厂 CT/DOT/L(I) 与主板真实脚号并行推进；合格 D0 证据且完成原生 CAD/磁件/厂商 SOA 后，才允许分档上 25/50/75/100 A。

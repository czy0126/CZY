# D1 P0 独立硬件保护：10门真实端子接口及执行卡（仅候选，未画入原生EDA）

## 0. 结论和资料等级

本轮将理想 PROT-B 十路0.05Ω钳位拆成**可采购的四片双通道门极缓冲驱动器候选**、8×真实VG至SR门极引脚映射、现有原边EN网络改造清单、硬故障/启动门槛双路径，以及18种故障注入验收矩阵。它不是保护已经实现，更不是安全硬件认证。

1. 原边使用现有 [TI UCC27282DRCR](https://www.ti.com/product/UCC27282/part-details/UCC27282DRCR) 的 `U2.6/EN`，故障关闭主桥；**现有R8=1kΩ到VCC12的上拉必须移除或DNP**，否则EN持续高；外部强拉低使R8产生144mW。保留R7=10kΩ到PGND以及C13 1nF（具体延迟要校准），采用独立默认低的主动SAFE_PRI_EN而非人工RUN jumper直连12V。TI UCC27282 Rev.B（2022）给EN典型关断延迟约1.5µs，此值非最坏保证，不能把它当理想纳秒级钳位。
2. 8只SR由4片 [TI UCC27524ADR](https://www.ti.com/product/UCC27524A/part-details/UCC27524ADR) 分别缓冲。原UCC24624的VG信号做**输入**，每片UCC27524A两个输出各通过既有2.2Ω电阻到一只SR门极。每通道独立ENA/ENB，故障锁存拉低全部8个EN，原驱动VG继续拉高也不会与额外低欧姆钳位直接硬碰。原厂 Rev.C（2024）第3页：`ENA=1,INA=2,GND=3,INB=4,OUTB=5,VDD=6,OUTA=7,ENB=8`。输入和使能允许12V范围（不代表瞬态噪声已验收）。
3. **失效安全风险**：UCC27524A的ENA/ENB内部有典型200kΩ上拉，悬空默认**使能**；建议从每个ENA/ENB加**独立本地4.7kΩ候选下拉**到SGND/PGND，再用独立安全许可信号主动拉高。典型200kΩ与4.7kΩ在12V产生约0.276V，**不能由典型值得出全温保证**；要用EN引脚最坏门槛、供电上升/下降、外部驱动电流与噪声逐项验收。EN持续被VDD短路属于一个新的单点故障，不能宣称已经容错。
4. **性能取舍**：UCC24624使用比例门极驱动调节VG电压；UCC27524A的非反相输入接收模拟VG后输出固定的高/低逻辑电平，**比例门极功能因此被破坏**。必须在200.6kHz、48/50V、轻载/突卸载与所有8只SR的反向电流/效率/VD监控时序中验证。若此问题无法接受，改用经额定验证的**模拟电平保留的输出隔离/负载门极驱动禁止结构**，不能直接生产该缓冲版本。
5. **真实延迟必须预算**：UCC27524A D版数据手册EN到输出典型13ns、最大发布23ns（指定1.8nF、5V使能输入、量测条件；开关参数不是逐件出厂生产测试）；UCC27282 EN约1.5µs典型。总体关断时间=CT变换/检测+比较器+锁存+传输+各驱动禁止+Rg/Cgate+Miller反充电，应按每路最慢与温度/寄生逐项签核。当前 PROT-B 的70ns/0.05Ω不能移作真实驱动时间。

## 1. 真实连接规则

来源 [机器可读10门保护接口](../../hardware/dcx_main/protection_interface_candidate.json)。U3–U6现有两路VG (pin1/8) 分别送 U7–U10新INA/INB (pin2/4)，U7–U10新OUTA/OUTB (pin7/5) 分别接原 `R20`–`R27` 的输入端，电阻输出保持连原SR栅极。必须核对U7–U10的6脚12V_S、3脚真实源极Kelvin PGND，且两路EN 1/8分别有物理下拉；不能把新缓冲器原理图数值自动当作已经在 `.eprj2` 里。原生网表里4组SR门极都在对PGND低边；一旦存在隔离地域，安全许可信号必须使用相应隔离/耐压传输，不能未经评估跨隔离直接并线。

## 2. 两条不同门槛的保护路径，不允许启动屏蔽造成死角

**硬保护**从上电开始一直启用：CT原边/次级监测可信、比较器供电健康、故障/灾难峰值检测及偏置掉电可使10门默认禁能。**快速优化保护**可以在完成软启动安全条件后才投入，避免旧PROT-B在启动阶段锁死。若启动电流峰36A而严重故障线性模型峰可超过100A，必须根据CT整流压降、CT饱和、Lr磁芯最大L(I)、比较器迟滞/延迟推算**最差允许硬限流动作区间**；不能把55A示例阈值直接当硬件签核。启动时禁掉全部保护会让硬短路无保护，绝对不能用。

## 3. 执行顺序及可操作的阻塞

**A（原生CAD）**：取消R8永久1k上拉并消除RUN测试跳线绕过；画独立硬件故障比较器+复位优先锁存+欠压检测和SAFE_PRI_EN；加入U7–U10具体8引脚、8个EN下拉、局部去耦和真实MPN，逐网/逐管做全网导出、ERC/DRC、DFM、10mm高度。此阶段必须先只做控制验证板，禁止接100A功率板。

**B（开关模型）**：新缓冲器先使用厂家原始PSpice模型（需记录许可/版次、输入允许范围和输出与温度），替换48V PROT-B理想钳位模型，先在12V电容性假门极测试所有电压/故障/时序，再对4×2 SR的完整功率级做48/50V全窗口，保留原始RAW/LOG/SHA。对UCC27282 EN真实延迟单独加门极关闭后的Lr能量、SR反向导通应力。

**C（失效注入）**：见 [18行专项测试矩阵](templates/protection_hardware_fault_matrix_18.csv)，每行都明确预期全部10门低、实际波形/量测、完成状态。特别检查R8误装、一个EN悬空/短VDD、UCC24624 VG持续高、主桥和次级分别失压、CT开路、软启动期短路。

**D（签核）**：按 `python tools/d1_protection_precheck.py --check` 验证当前现存10门逻辑网和候选连接契约。该命令只可返回“接口记录一致，但真实保护未实施”；不得作为 `tools/d1_fabrication_gate.py --require-release` 的替代。后者在未落实真实ERC、保护、磁件实物及SOA前必须失败。

## 4. 哪些事情无法仅靠在线操作完成

无法凭空得知5磁件24实际端子或CT DOT、无法取得物理真实的L(I)与高温第三象限SOA、无法虚构GUI ERC/带网PCB和首样故障波形。都已列为输出具体图纸或实验的责任，而不是把全部61件都交给厂家等回复。

# 第31章 · D0 多仪器同步对齐与重采样（第29章的前置工具）

> **状态：可执行的软件对齐工具，尚无真实台架数据。** 本章交付 `tools/d0_scope_sync_align.py`、负向回归测试和一份全 `PENDING` 的 manifest 模板。它只把多台示波器的记录按各自的触发沿搬到同一时间轴，并写出第29章要求的 12 列 CSV；**不证明物理同时性、不认证波形来源、不代替第29章的门极验收，更不放开制造闸门。**

## 一、为什么需要它

[第29章](29_D0十路门极同步波形证据验收.md) 的硬条件是：12 列必须**共享同一个时间基准**；原文明确写道：

> 若用多台示波器需先证明同步精度并在另一个经审核的重采样工具中处理；本程序不会也不应猜测时轴偏差。

`d0_gate_capture_audit.py` 只能消费一条已经对齐的 CSV。台架上两台仪器的采样时钟、触发延迟和记录起点通常不同；如果直接把两段 CSV 拼起来，软件会以为它们同步，从而把纳秒级错位误判为“晚关断”或“提前关断”。本章的工具把这件事显式化：**先由工程审核人声明同步依据与剩余偏差预算，再由程序检查采样分辨率是否支持这个预算，最后才重采样。**

## 二、它做什么、不做什么

**做：**

1. 在每台仪器的记录里寻找**恰好一个**声明触发沿（上升或下降），用相邻样点线性插值定位到亚采样时刻；
2. 以每台仪器自己的触发时刻为零点，把记录搬到共同网格；
3. 用线性插值重采样到 `dt_s` 网格，并强制 **`dt_s` 不细于所有原始记录中最粗的采样间隔**——不凭空制造分辨率；
4. 输出严格 12 列：`time_s`, `TRIP_STIMULUS`, `P_HO`, `P_LO`, `SR1A`…`SR4B`，列序与第29章审计器一致；
5. 报告每台仪器的 CSV SHA-256、实测采样率、触发插值不确定度、覆盖区间，以及声明的同步预算是否被采样分辨率支持。

**不做：**

- 不证明两台仪器在物理上同时采样；`physical_simultaneity_proven` 恒为 `false`；
- 不测量探头 skew、触发抖动、带宽差异、通道间传播延迟；
- 不认证 CSV 来自真实仪器；`waveform_origin_authenticated` 恒为 `false`；
- 不外推：任一仪器覆盖不到自己的对齐窗口时直接失败，不在端点外插值；
- 不放行硬件保护、器件 SOA 或制造；`hardware_protection_approved`、`power_stage_fabrication_approved` 恒为 `false`。

## 三、manifest 格式

模板见 [d0_scope_sync_manifest_TEMPLATE.json](templates/d0_scope_sync_manifest_TEMPLATE.json)。所有值都是 `PENDING`/`null`，**直接运行必定以退出码 2 拒绝**；这是有意的。

| 字段 | 含义 |
|---|---|
| `schema_version` | 必须为 `1` |
| `case_id` | 本次事件标识；不是硬件签核号 |
| `sync.alignment_basis` | 同步依据的文字说明，例如“同一 10 MHz 参考”“公共触发脉冲经同一探头分配器” |
| `sync.basis_review_status` | 只有 `ENGINEER_REVIEWED` 才可能得到退出码 0 |
| `sync.max_remaining_skew_s` | 审核人声明的**剩余偏差上限**（秒），必须为正 |
| `grid.pre_s` / `post_s` / `dt_s` | 共同网格：故障前/后时长与步长；`pre_s`、`post_s` 必须分别是 `dt_s` 的整数倍 |
| `instruments[].id` | 本 manifest 内的唯一标识 |
| `instruments[].csv` | 记录文件；相对路径按 manifest 所在目录解析 |
| `instruments[].time_column` | 时间列名，通常 `time_s` |
| `instruments[].trigger.column` | 用于对齐的源列名；它可以同时是某个输出通道 |
| `instruments[].trigger.edge` | `rising` 或 `falling`；`TRIP_STIMULUS` 的生产者必须是 `rising` |
| `instruments[].trigger.threshold_v` | 触发阈值；建议与第29章配置的 `trip_high_min_v` 相同 |
| `instruments[].trigger.search_start_s` / `search_end_s` | 只在这段窗口内找沿；窗口必须落在记录内，且**恰好一个**沿 |
| `instruments[].channels` | `源列名 -> 目标通道` 的映射；11 个目标通道必须各有且仅有一个生产者 |
| `instruments[].instrument_id` / `probe_model` / `probe_bandwidth_hz` | 仪器与探头元数据；任一缺失只降为“来源不完整”，不阻止写 CSV |
| `instruments[].sample_rate_hz` | 声明采样率；程序用 `(n-1)/(t_last-t_first)` 复核，偏差超过 2% 即失败 |

**参考触发的约束：** `TRIP_STIMULUS` 的生产者必须用**映射到 `TRIP_STIMULUS` 的那一列**作为触发列，且触发沿必须是上升沿。这保证“所有仪器对齐到同一个物理故障激励”，而不是各自对齐到任意同步脉冲。

## 四、算法与 fail-closed 判据

1. **读入**：UTF-8-sig，表头不得重复，必需列必须存在，每行列数一致，所有值有限，时间严格递增，至少 5 个样点。manifest 的 JSON 重复键直接失败（`json` 默认会静默折叠重复键，这里不允许）；同一仪器内两列映射到同一目标通道也直接失败，防止把一条波形复制成两路。
2. **找沿**：在 `[search_start_s, search_end_s]` 内，按 `left < threshold <= right`（上升）或 `left > threshold >= right`（下降）计数；**0 个或 >1 个都直接失败**。命中后用 `t = t_left + (threshold-v_left)/(v_right-v_left)·Δt` 定位，触发不确定度取该相邻间隔的一半。
3. **采样率复核**：声明值与实测值相对差 > 2% 即失败。这只是粗检，不是校准。
4. **预算检查**：取“触发插值不确定度”和“重采样插值不确定度（最粗间隔的一半）”的较大者，要求 `≤ max_remaining_skew_s`。**程序只检查声明的预算是否被采样分辨率支持；预算本身是否真实，要靠审核人给出依据。**
5. **网格分辨率**：`dt_s` 必须 `≥` 所有记录的最大相邻间隔；否则失败，理由写明“会制造分辨率”。
6. **覆盖**：每台仪器必须覆盖 `[触发时刻 - pre_s, 触发时刻 + post_s]`，否则失败；程序从不在端点外插值。
7. **对齐后复核**：在输出 CSV 上重新找一次 `TRIP_STIMULUS` 的上升沿，必须**恰好一个**，且位于共享原点附近（容差为 `dt_s + 触发不确定度`）。

失败时**不写输出 CSV**，只写一份 `status=INVALID_ALIGNMENT` 的报告并返回 2。成功但对齐依据未审核或仪器元数据缺失时，**仍写 CSV**，但 `status=ALIGNED_PROVENANCE_INCOMPLETE`，返回 1。

## 五、使用方法

```powershell
# 1) 复制模板并填写真实仪器、路径、阈值、预算（不可直接运行模板）
Copy-Item docs/D1_EXECUTION_KIT/templates/d0_scope_sync_manifest_TEMPLATE.json out/d0_scope/sync.json

# 2) 对齐：输出第29章可直接消费的 12 列 CSV
python tools/d0_scope_sync_align.py --manifest out/d0_scope/sync.json `
    --csv out/d0_scope/aligned.csv --report out/d0_scope/aligned.json

# 3) 用第29章工具做门极验收（限值仍需独立审核）
python tools/d0_gate_capture_audit.py --csv out/d0_scope/aligned.csv `
    --config out/d0_scope/limits.json --output out/d0_scope/audit.json

# 4) 回归
python -m pytest tools/test_d0_scope_sync_align.py -q
```

**退出码：**

- `0` `ALIGNED_FOR_CAPTURE_AUDIT`：结构、分辨率、覆盖与来源元数据齐全；**仍不是硬件证据**；
- `1` `ALIGNED_PROVENANCE_INCOMPLETE`：CSV 已写，但 `basis_review_status` 不是 `ENGINEER_REVIEWED`，或某台仪器缺 `instrument_id`/`probe_model`/有效 `probe_bandwidth_hz`；
- `2` `INVALID_ALIGNMENT`：manifest 结构错误、缺通道、重复生产者、触发沿 0/多个、采样率不符、预算不足、网格过细、覆盖不足、CSV 非法等；**不写输出 CSV**。

## 六、必须由工程审核人决定的事

- **同步依据**：两台仪器的时基是如何共同的？同一参考时钟、同一外部触发、还是公共信号注入？程序不会从数据反推这一点。
- **剩余偏差预算**：`max_remaining_skew_s` 必须来自仪器规格与实测（例如同一信号经分配器进两台仪器，测得的通道间偏差），不能因为“程序通过了”就认为预算成立。
- **触发阈值与第29章门槛的一致性**：建议 `trigger.threshold_v` 等于第29章配置的 `trip_high_min_v`。对齐后原点样点正好落在阈值附近；若第29章的高电平门槛更高，原点样点可能落在 `trip_low_max_v` 与 `trip_high_min_v` 之间，被审计器判为 `ambiguous TRIP_STIMULUS logic level`。
- **窗口**：`pre_s`/`post_s` 必须覆盖第29章的 `min_pretrip_s` 与 `max_disable_latency_s + min_post_trip_hold_s`，否则对齐后的 CSV 会在下一步被拒绝。

## 七、能力边界与后续

本工具的测试波形全部是合成的，**任何测试通过都不能引用为台架证据**。它不读取示波器原生文件，不校验探头衰减、带宽、共地、隔离或安全等级；这些仍按第29章与 [Issue #36](https://github.com/czy0126/CZY/issues/36) 的实物流程执行。

**最短真实路径：** 先完成 D0 十路低能量保护电路与真实采集；用本章工具对齐；再用第29章工具做逐通道 VGS 验收。只有真实 D0 证据、原生 CAD、磁件 24 端子和厂家 SOA 都完成后，才允许按 25/50/75/100 A 分档上功率。当前制造闸门仍是 `NOT_FOR_FAB`。

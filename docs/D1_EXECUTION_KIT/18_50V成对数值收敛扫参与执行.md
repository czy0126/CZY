# 第18章：解决50V严格配对停算的成对数值收敛扫参

目标：原有**同模型配对控制**虽在故障前完全配对（0mV偏差），但A/B分别停算250.151/254.980µs，无法和各自的完整320µs候选比较。禁止使用另一套`Vt=10`门极开关控制（故障前Vout差13–18mV）来凑齐两个条件。

本包在完全相同的既有四组电路上，只改变LTspice `.options cshunt`，按成对同参数方式生成 12份诊断deck：2fF、5fF、10fF，每一种都包含 `A_CONTROL/A_CANDIDATE/B_CONTROL/B_CANDIDATE`。**这是数值敏感性研究，不是添加实际并联电容、不是硬件保护方案，也不表明已收敛。**

## 本次新增的实际可执行文件

- 12份 `.cir` 已存储于 `sim/v3/d1_prot03_shunt_{2f,5f,10f}_{A_CONTROL,A_CANDIDATE,B_CONTROL,B_CANDIDATE}.cir`；每份含源模型和完整320µs窗口，只有 `.options cshunt` 与两行标识注释发生变动。
- 受控 [12例执行清单](../../design/v3/power_priority/prot03_solver_sweep_plan.json) 的 `simulation_state` 全为 UNRUN、`not_for_fab=true`，不能把“生成”写成“仿真完成”。
- `python tools/generate_prot03_solver_sweep.py --check` 逐文件与原deck比较；`python -m pytest tools/test_generate_prot03_solver_sweep.py -q` 拦截任何非cshunt电路改变。

## Windows执行

先做最小2fF组，以便检查是不是数值卡死所致：

```powershell
pwsh -File tools/run_d1_50v_matched_cases.ps1 -Variant shunt_2f
pwsh -File tools/run_d1_50v_matched_cases.ps1 -Variant shunt_2f -Cases B_CONTROL,B_CANDIDATE -Execute -RunId solver_2f_B_001 -LTspice 'C:\Program Files\ADI\LTspice\LTspice.exe'
```

若在2fF下仍无法得到完整对照，再同样使用`shunt_5f`和`shunt_10f`。**每种cshunt都必须控制+候选成对运行**，不允许用1fF候选与5fF对照混合。脚本继承之前的不可覆盖/RAW/LOG/哈希记录。输出文件保存失败前缀和完整运行状态后，再用 `protection_candidate_compare.py` 成对重算新JSON，不覆盖历史发布的PROT-03报告。

本机执行策略禁止运行 `.ps1`（`powershell -File` 直接 `UnauthorizedAccess`），因此同一契约由 Python 移植版执行，`-Variant` 对应 `--variant`：

```bash
python tools/run_d1_50v_matched_cases.py --variant shunt_2f            # dry-run，只列 deck
python tools/run_d1_50v_matched_cases.py --variant shunt_2f --execute \
    --run-id solver_2f_B_001 --cases B_CONTROL B_CANDIDATE \
    --ltspice D:/ADI/LTspice/LTspice.exe
```

移植版的 cshunt 门槛按变体取值（`published`=1e-15、`shunt_2f`=2e-15、`shunt_5f`=5e-15、`shunt_10f`=1e-14），所以“1 fF 候选配 5 fF 对照”会被直接拒绝；`run_manifest.json` 还额外记录 `variant` 与 `required_cshunt_farads`，扫描归档不会被误当成已发布的 1 fF 证据。

## 可接受判据和失效条件

1. 每组控制与候选双方最后保存时间均达到320µs，原始日志包含`Total elapsed time`，不仅是求解器处理了部分波形。
2. 140–175µs故障前Vout均值差≤1mV；在同一控制类、相同器件与开关模型下对比。
3. 2fF、5fF、10fF对峰值、起动瞬态与故障后8SR门极的影响必须另列；若cshunt变化导致主电路工作点或门极末态显著改变，就只能归为**数值敏感性**，不是“保护有了确定收益”。
4. 完整判断需要真实比较器、UCC27282 EN及NCP4306/UCC27524A的门级关断延时模型。旧PROT-B `0.05Ω`理想钳位与新物理实现不同。第三象限SOA/磁件L(I)依旧阻塞。

## 本机复跑：1 fF 四例的第二次独立执行

`python tools/run_d1_50v_matched_cases.py --execute --run-id d1_50v_20261103` 在同一台机上重跑了四份已发布的 1 fF deck（归档 `out/d1_50v/d1_50v_20261103/`，raw/log sha256 记入 `simulation_run_register_PROT03_rerun_2026-11-03.csv`）：

| 用例 | 结果 | 时长 | 说明 |
|---|---|---|---|
| A_CANDIDATE | 跑满 320.000 µs | 1222.307 s | 日志含 `Total elapsed time` |
| B_CANDIDATE | 跑满 320.000 µs | 1383.502 s | 同上 |
| A_CONTROL | 停在 **250.150953 µs** | 1800 s 超时 | 无 `Total elapsed time`；前次 250.151 µs |
| B_CONTROL | 停在 **254.980494 µs** | 1800 s 超时 | 前次 254.980 µs |

配对复算写入**新** JSON（不覆盖已发布记录）：`protection_candidate_50v_120a_prot_{a,b}_paired_d1_50v_20261103.json`。两组故障前 `V(out)` 均值差都是 **0.000000 mV**；A 触发 215.170 / 锁存 215.240 µs、SR 正向峰 304.960 A、I²t 0.598912 A²s；B 触发 185.270 / 锁存 185.340 µs、SR 峰 139.354 A、I²t 0.033040 A²s。这些物理量与已发布 JSON 的对应字段相同，只有窗口终点差 **0.08 ns**（相对 3.2e-7，来自两次运行尾部采样不同）——停滞是这套 deck 的确定性属性，不是单次运行偶发。

两条判据在 1 fF 下仍然互斥（见 `PROT02_独立故障锁存候选对照_2026-11-03.md` §5.6/§7）；复跑没有改变该结论，只补上了“可复现”这一条。四例的 `run_manifest.json` 由 21:01 之前载入的模块产生，因此没有 `variant`/`required_cshunt_farads` 两个后加字段——四行的 `source_sha256` 已锁定为已发布 deck，来源仍可逐份核对。

本文档最初那句“本轮未在当前环境运行 LTspice”只对生成器发布那一刻成立；现在的事实是“1 fF 四例已复跑，2 fF 的 A 组成对完成，2 fF 的 B 组与 5 fF / 10 fF 未运行”。

## 2 fF 组：配对控制第一次跑满 320 µs

`--variant shunt_2f` 的 **A_CONTROL**（run `solver_2f_A_001`）跑满 **320.000 µs**（457.205 s，1.17 GB）。这是 50 V 的 thrmute 配对控制第一次走完整个保存窗口——1 fF 下它每次都停在 250.151 µs。

**只加 2 fF 没有把物理改掉**（`hotfault_convergence.py`，两侧都取 0–220 µs 冻结窗口，`circuit_differences()` 为 0 条，`checks` 全绿；记录 `solver_sweep_2f_A_CONTROL_convergence.json`）：

| 量 | 1 fF 控制 | 2 fF 控制 | 相对 |
|---|---|---|---|
| trip | 215.1704 µs | 215.0232 µs | −147 ns（−0.068 %） |
| `I(Lr)` 峰 | 100.988 A | 101.069 A | +0.080 % |
| SR 正向峰 | 304.960 A | 303.411 A | −0.508 % |
| SR 反向峰 | 13.339 A | 13.759 A | +3.15 % |
| `V(oc)` 最大 | 1.0871 V | 1.0901 V | +0.28 % |
| 故障后 `V(out)` 最低 | 0.9341 V | 0.9449 V | +1.15 % |

三个头部峰值移动都在 1 % 内；唯一大幅移动的是 SR 反向峰（+3.15 %），它与最初引入 1 fF 时移动 −1.67 % 属于同一类“接近零、斜率大”的量，因此按数值敏感性引用，不能当电路变化。采样步数从 986 420 降到 432 537（同一 220 µs 窗口，2.28 倍），说明省下的是求解步而不是求解精度之外的物理。

**窗口必须写 220 µs，不能写成 250 µs**：同一条比较若把窗口放到 250 µs，两侧 raw 在 249.997 / 249.998 µs 之后就没有采样点，`the_comparison_window_is_covered_by_both_raws` 会（正确地）报 false；`vout_min_after_engage_v` 的符号也会随窗口翻转（250 µs 窗口是 −1.14 %）。220 µs 是既有 SOLVER_DIAGNOSTIC 的冻结窗口，也是这里记录的那个。

候选侧（run `solver_2f_A_002`）随后也跑满 **320.000 µs**（440.638 s、1.11 GB）。用同一 2 fF 的两条 raw 成对复算（必须显式传 `--base-deck`/`--candidate-deck`，不能用 1 fF 的默认父 deck——`mixed_sweep_variants()` 现在把这条写成硬错误，混用两种 cshunt 会在读 raw 之前就被 CLI 拒绝）写出 `protection_candidate_50v_120a_prot_a_paired_shunt_2f.json`，**七项 `checks` 全为 true**，包括一直为 false 的 `the_declared_window_is_fully_covered`：

| 量 | 2 fF 控制 | 2 fF 候选 |
|---|---|---|
| 尾部保存时间 | 320.000 µs | 320.000 µs |
| 故障前 `V(out)` 均值（140–175 µs） | 1.943736647 V | 1.943736647 V（差 **0.000000 mV**） |
| trip | 215.0232 µs | 215.0232 µs |
| 锁存 | 215.0925 µs（延时 69.3 ns） | 215.0925 µs |
| SR 正向峰 | 303.411 A | 303.411 A |
| SR 正向 I²t 合计 | 4.753844 A²s | 4.721685 A²s（**−0.676 %**） |
| 故障后 `V(out)` 最低 | 0.7444 mV | 0.7328 mV（差 −0.0116 mV） |
| 八只 SR 门极末端为高 | 0 只 | 0 只 |

这是 50 V 第一次**同时**满足“两侧跑满 320 µs”和“故障前 ≤1 mV”两条判据——1 fF 下它们互斥。三处必须照原文读，不能外推：

- 峰值两侧逐位相同，因为两 deck 在触发前逐位相同（1 fF 配对也是这样），不是“保护没有作用”；候选的收益体现在 I²t（−0.676 %）与门极关断时序上。
- 控制端门极在 trip 后**回到高电平直到 237.459 µs**才落下，末端为高的只数（1 fF 3 只、2 fF 0 只）是**求解器选的末态**，不是“2 fF 更安全”。`all_candidate_gates_low_at_end` 只说明候选侧这一刻的记录，`hardware_continuous_rating_approved` 与 `safety_proof` 都仍是 **false**。
- `cshunt=2e-15` 是求解器正则化，不是电路里加了电容；本组只说明**此数值设置下的成对可比性**，`fabrication_approved` 仍为 false。

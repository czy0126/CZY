## 1. 关键修复：错误的软启动完成判据

`tools/validate_hotfault_log.py` 原来要求故障前 `4.8≤V(ss)≤5.1 V`。然而 `models/ucc25600_legacy_behaviour.lib` 的等效 RT 频率律是：

`Ieff = max(0, 1.81 mA - V(ss)/2200Ω)`

因此 **RT 单独控制频率的临界值为 3.982 V**，并不是 4.8 V。现有稳态候选 `.ic V(ss)=4V`，仿真注释中记录 20µs 时约3.987 V、500µs 时约4.227 V；旧判据会把正常工作点错误判为未稳定，引起无效返工。

**已修改**为 `3.982V≤V(ss)≤6.05V` 的 RT-only 频率区间。注意这**只是频率模式门槛，不能独立证明输出已稳定**；为此两份独立故障 deck 追加 `HOT_VOUT_EARLY`（120–145µs）和 `HOT_VOUT_LATE`（145–170µs）两个故障前均值，要求差值小于 `max(10mV, 0.5%稳态参考)`，且整个 120–170µs 均值应在与同电压母本稳态值的 `max(20mV, 2%)` 以内。仍需要后续的 RAW 波形核查控制频率、OC 动态和半桥关断状态。

`tools/d1_unclosed_risks.py` 的 F01 原来同样使用 `Vss<4.8V`，现在改为与日志验收共享的 **3.982 V** 门槛。既有 48 V 冷启动故障投入时 `Vss=3.7815 V`，仍属于真正的启动阶段故障，因此 F01 **仍为 P0 BLOCKED**。

### 本轮没有伪造的结论

- 50V/110A、50V/120A 稳态模型已经有 LTspice 运行记录（约109.64A/213.99W、119.27A/231.87W）；两份新 hot-fault 只准备了 deck，**仍未运行**。
- 48V/120A 真冷启动已跑完 8ms，但过载故障记录只到7.571ms；软启动时原边约84.83A故障峰值不能当稳态后、50V下最严情形。
- 50V/120A 能量账本约0.499W损耗缺口未定位，0.2W约束不变。
- 100A 门极边界后处理残差约0.09W，但二极管损耗的步长收敛仍有争议；不发布连续额定、效率认证或真实 SOA。

## 2. 直接可以发给供应商的两份工程 CSV

从已核查的 `vendor_terminal_request.json` 与 `component_decision_register.json` **自动生成 CSV**，减少后续由文档手抄到 Excel 导致的错误：

| 文件 | 行数 | 收件人 | 必须反馈的证据 |
|---|---:|---|---|
| `hardware/dcx_main/supplier_magnetic_terminal_reply_template.csv` | **24 端子**（T1–T4 各5、CT 4） | 定制磁件厂家/磁件工程师 | 真实物理 pad 编号及位置、DIM 图纸及修订版、DOT/变比、CTAP、实物封装、首件极性记录 |

生成命令：

```bash
python tools/export_d1_vendor_packets.py --write  # 根据最新 JSON 重生模板
python tools/export_d1_vendor_packets.py          # 比对已提交模板
```

**签核边界**：新 CSV 的供应商回填列一律空白，`pad_map_reviewed=NO`、`decision=PENDING`；不是采购定单或已确认引脚。供应商应将已填写的**回复文件另存**为带日期/版本的独立交付，原模板保持可再生，不要直接编辑生成文件再覆盖。高优先级为磁件、Lr、Cr、Cin、Cout、D_BT、连接器；常规 R/C 可以让采购工程师并行处理。

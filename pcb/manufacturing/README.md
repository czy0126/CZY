## What each board is

### `sr_fault_validation` -- Single-pair UCC24624 SR fault-shutdown validation board

Two BSC010N04LS6 driven by one real UCC24624, a fault interface and a REG crowbar.  Its purpose is to measure how one SR pair behaves when a fault command arrives, not to pass the converter's current.

Package: `pcb/sr_fault_validation/fab/` (manifest `420937f186527d7e243629d25045215632ace9d044cf238014dd86d3867ffc27`)
Board: `pcb/sr_fault_validation/sr_fault_validation.kicad_pcb` (`577d58ed8f906d7659f3c95be5860b8a14cd35cc3e579268a8a8b79fde0727d4`)
Layers: F.Cu, B.Cu, F.Paste, B.Paste, F.Silkscreen, B.Silkscreen, F.Mask, B.Mask, Edge.Cuts

### `fast_oc` -- TLV3501 fast-overcurrent ECO module

One TLV3501 comparator and a 2N7002 open-drain pull-down that make the overcurrent channel fast by replacing the three RC filters, not the comparator.  It does not latch.

Package: `pcb/fast_oc/fab/` (manifest `cdadf17d0ac24b01bcad1608f24ba0b0629fefde7aa77470aae4a9e890e78ee2`)
Board: `pcb/fast_oc/fast_oc.kicad_pcb` (`c88a1b1add5c2f88a16cbdd7bd734c9dc4ce397c9ed1cd1a6192456d2d91d81b`)
Layers: F.Cu, B.Cu, F.Paste, B.Paste, F.Silkscreen, B.Silkscreen, F.Mask, B.Mask, Edge.Cuts

### `d0_protection` -- D0 ten-channel protection logic board

CD4013 fault latches, the ten-way gate-maximum detector (one Schottky per gate into a 22k/6.2k divider, replacing the ten-resistor sum) and the ACK token, with the POR folded into the latch.  Schematic and ERC only.

### `control_validation` -- UCC25600 / UCC24624 control validation board

The controller and SR driver wired to their passives so the timing, RT/DT and dead-time assumptions can be measured before the power stage exists.  Schematic and ERC only.

## Rebuilding a package

```
python tools/make_sr_fault_board_pcb.py --fab
python tools/make_fast_oc_pcb.py --fab
python tools/make_d0_protection_board.py --check
python tools/make_control_board.py --check
```

The two `--fab` commands need KiCad's kicad-cli.  Without it the committed packages can be inspected and hashed, but not rebuilt.

## What this directory is not

- **Not an approval.**  `hardware_built` and `fabrication_approved` are false
  on every board.  A package that can be ordered is exactly the artefact that
  gets mistaken for an approved one.
- **Not a bill of materials.**  Each board's `BOM.csv` is next to its
  schematic; the main board's sourcing state is in
  `hardware/dcx_main/placeholder_eco.json`.
- **Not the main board.**  It has no copper; see
  `hardware/dcx_main/remaining_dependencies.md`.

## 1 这次跑的是什么

两份 deck 都由 `tools/make_120a_transients.py` 从**真正的零初态**母本（`cold_phys` /
`cold_oc_phys`）生成，只把 `.param` 里的 `RL=20m` 改成 `RL=15.4m`：

| 项 | 冷启动 | 过载故障 |
|---|---|---|
| 母本 | `cold_phys` | `cold_oc_phys`（含 5.5–5.6 ms 故障支路） |
| `.tran` | `0 8m 0 10n uic` | 同 |
| `.ic` | **没有**（`uic` 即零初态） | **没有** |
| 变量数 | 37 | 37 |
| 运行时长 | **2294.151 s** | **2469 s**（被终止） |
| raw | **13 087 933 540 B**（约 12.2 GiB） | **11 552 302 933 B**（约 10.8 GiB） |
| 时间轴 | 到达 **8 ms** | 到 **7.5714 ms** 后塌缩 |

**“120 A”仍是负载电阻的目标，不是结果。** `RL=15.4 mΩ` 由稳态 121.67 A 那次仿真反推；
冷启动末端的实际电流是 `V(out)/RL`。`test_the_cold_record_keeps_120a_as_the_load_not_the_result`
禁止把 120.0 A 写进结果列。

故障支路是 `Sflt`（`Ron=1m`）串 `Rflt=1m`，在 5.55 ms 并入负载：

```
Vfltctl ctl 0 PWL(0 0 5.5m 0 5.6m 5 8m 5)
Sflt out flt ctl 0 SFLT
Rflt flt 0 1m
```

`15.4 mΩ || 2 mΩ = 1.77011 mΩ`，即 **8.70 倍**过载。母本头注写的
`1.818 mΩ / 11×` 是它自己 20 mΩ 负载的比值；`test_the_fault_record_takes_its_severity_from_the_deck`
锁住本次必须报 8.70×。

2026-11-03 补了一个**只改求解器选项**的收敛诊断子 deck（`..._cold_oc_vin48_i120_target_cshunt.cir`），
用来检验“cshunt 能不能让 8 ms 跑完”。结论是**不能**，而且比基座更早塌缩；详见 §9。
这不是第三条证据 deck，基座记录仍是唯一的已发布故障数据。

## 3 过载故障：trip 与关断

**这次运行没有跑完 8 ms。** 求解器在 **7.571410 ms** 处步长塌缩（两分钟内时间只前进
约 1e-11 s，点数仍在增加），按 PID 结束进程，已写出的前缀保留为证据。因此：

- `reached_tstop = false`、`solver_prefix_only = true`；
- 日志里**没有** `Total elapsed time`，也**没有** `.meas` 块——被终止的 LTspice 不写测量结果；
- 故障段可引用的区间是 **5.55–7.5714 ms**，不是 5.55–8 ms。

| 跳闸前 `I(Lr)` 峰值 | **84.827 A @ 5.58069 ms** | 84.017 A |

`✶ Insight ─────────────────────────────────────`
- **故障落在软启动途中，不是稳态**：投入时 `V(ss)=3.78 V`（满量程 5 V），`V(out)` 也只有
  1.853 V。母本故障块的头注声称启动“已稳定在 200.6 kHz 设计点”，这两个字段就是为了
  不继承那句话而加的（`vout_at_engage_v` / `ss_at_engage_v`）。引用本组数据时必须写
  “软启动途中投入”，否则会把故障后的跌落归因于“稳态被拉垮”。
- **trip 延迟 41.8 µs 是本 deck 的值，不是保护规格**。它由 `V(oc)` 的 RC/分压链和
  8.70× 的电流斜率共同决定；换负载、换 OC 网络都会变。两个工况的延迟差 8 µs，
  不能外推成“保护足够快”。
`─────────────────────────────────────────────────`

与母本相比，本次过载倍数更低（8.70× 对 11×），投入前负载电流更高（121.7 A 对约 94 A），
于是 trip 早约 8 µs、峰值略高（84.83 A 对 84.02 A）、`V(oc)` 最大值略低、
`V(out)` 没有像母本那样被拉到 −43.7 mV。5.6–5.8 ms 窗口的 48.45 A 明显低于母本的
73.12 A；本文只报数，不解释两者的差异（两次运行的故障前后驱动状态并不相同）。

SR 的 255.22 A 峰值出现在 **5.5807 ms**，即 trip（5.5918 ms）之前、塌缩（7.5714 ms）
之前约 2 ms，**不是塌缩尾部的采样伪影**。四路检测里 `I(VSb1)` 最大，
`I(VSa1)=254.48 A @ 5.5831 ms`，两组几乎对称；它们与 `I(Lr)` 峰值同一时刻，
是故障电流经变压器传到副边的结果。

## 4 磁通：2 匝在故障峰值下仍越过 Bsat

按项目口径 `B = L·I/(N·Ae)`，`L` 取这次运行的 **1.0 µH**（`paired_flux()` 用测量时
配对的电感，不拿别的电感换算），`Ae=1.3e-4 m²`、`Bsat=0.31 T`、判据 `0.9·Bsat=0.279 T`：

| 峰值来源 | `I(Lr)` | 2 匝 B | 3 匝 B | 结论 |
|---|---:|---:|---:|---|
| 冷启动 | 24.134 A | **0.0928 T** | 0.0619 T | 2 匝/3 匝都安全 |
| 过载故障（trip 前） | **84.827 A** | **0.3263 T** | **0.2175 T** | **2 匝 > Bsat（0.310 T）** |

- 2 匝的 `Isat = 80.6 A`，本次峰值 **84.83 A 已超过它**；即使用 0.279 T 判据，
  2 匝也是 1.17 倍，3 匝是 0.78 倍。
- 这与物理 deck 的 84.02 A / 0.323 T 是同一结论，本次峰值再高 1 %。
  **BOM §3.3 里“首件漏感 ≥20 nH 就能把 2 匝救回 0.9 判据”只对冻结 deck 的
  73.68 A 成立**，已被 84–85 A 的故障峰值两次推翻。故障设计应按 3 匝（或更大 Ae）校核，
  且 65/74/85 A 这些数都来自**线性** Lr 模型——真实饱和后 di/dt 更高，
  这里的 B 是下界意义上的设计点，不是器件的失效边界。

## 5 模型边界

1. **故障段是不完整区间**：7.5714 ms 后求解器塌缩，本文所有“末端”量都指 7.5714 ms，
   不是 8 ms。塌缩原因未定位；按项目规则只记录可达前缀与终止原因，不猜。
   **§9 已试过 50 V 上奏效的 `cshunt=1 fF` 补救，对这个 deck 不奏效**：变体在
   5.6141 ms 就塌缩，比基座还早 1.96 ms；公共前缀上的故障峰值只动 0.04–0.07 %。
2. **`V(oc)` / 驱动是行为模型**：trip 延迟和最长关断 193.43 µs 由 deck 里的比较器/
   驱动行为决定；真实 UCC25600 的 Level-1 响应、软启动重试与 SR 驱动时序没有建模。
3. **不是器件 SOA**：84.83 A、255.22 A（SR）都出自线性器件模型；没有结温、没有
   饱和后的电感下降、没有 PCB 寄生。SR 的 255 A 尤其不能当器件电流额定来用。
4. **冷启动的 228.0 W 是端口值**：负载就是 15.4 mΩ，没有输出铜排/接点、没有磁芯损耗、
   没有偏置完整归属。加 0.15 mΩ 外部路径是换算，不是模型结果。
5. **raw 不入 Git**：两份约 12.2 GiB / 10.8 GiB；提交的证据是两份 JSON、deck 与本文。

## 6 不能下的结论

1. **不是 120 A 连续额定**：没有热数据、没有真实均流、没有 SR 结温、没有输出路径。
2. **不是保护认证**：一次 8.70× 过载、一个未跑完的窗口，不能证明短路、重复过载或
   软启动重试下的安全。
3. **不能由本次故障峰值反推 100 A/110 A**：投入前电流、软启动状态与故障倍数都不同。
4. **不能把 7.5714 ms 的末端当成“故障后稳态”**：输出已经跌到 −3.6 mV，变换器处于
   关断/重试过程，没有稳态可言。

## 9 塌缩的收敛诊断：cshunt 不奏效（2026-11-03）

**问题**：50 V 稳态初始化故障在 296.929 µs 塌缩，只加 `cshunt=1 fF`（200 kHz 下
795 kΩ）就让它跑满 320 µs。同一个补救能不能让这条 8 ms 冷启动过载跑完？

**答案：不能，而且更早塌缩。**

记录：`cold_oc_vin48_i120_cshunt.json`；工具：`tools/cold_oc_convergence.py`；
变体 deck：`sim/v3/sr_tank_dual_v33_cold_oc_vin48_i120_target_cshunt.cir`
（`make_120a_transients.py` 从基座派生，**只**在 `.options` 行追加 `cshunt=1e-15`）。
`circuit_differences()` 对两份 deck 返回 **0 条**：电路、故障支路、`.tran`
（`0 8m 0 10n uic`）与全部 `.meas` 逐行相同。

| 项 | 基座 | cshunt 变体 |
|---|---|---|
| 最后保存时刻 | **7.5714 ms** | **5.6141 ms** |
| 是否到 8 ms | 否 | 否 |
| raw 大小 | 11.55 GB | 9.03 GB（被终止前） |
| 日志 `Total elapsed time` | 无 | 无 |
| 日志 `.meas` | 无 | 无 |
| 公共窗口 5.4–5.614 ms 采样点 | 429 100 | 1 343 952 |
| trip | 5.591809 ms | 5.592389 ms |
| 投入→trip | 41.809 µs | 42.389 µs |
| I(Lr) 峰（trip 前） | 84.8268 A @ 5.58069 ms | 84.7927 A @ 5.58311 ms |
| SR 正向峰 | 255.2247 A | 255.0407 A |
| V(oc) 最大 | 1.20019 V | 1.19931 V |
| 窗口内 V(out) 最低 | 0.22362 V | 0.22996 V |

**公共切片上的移动量**：trip **+580 ns**（相对 +1.04e-4）、I(Lr) 峰 **−0.040 %**、
SR 正向峰 **−0.072 %**、V(oc) 最大 −0.074 %。V(out) 最低是“接近零、斜率大”的量，
只报相对值（+2.84 %），不参与判据。

**怎么读这三个事实**：

1. **补救失败**：变体不是“跑得更久”，而是**早塌 1.96 ms**。所以 cshunt 不是一个
   可复用的“让塌缩跑完”的开关；50 V 那次成功不能外推到这条 deck。F02 因此仍
   `blocked`，而且“再试 cshunt”已被排除。
2. **峰值不是这个求解器设置的伪影**：公共切片里所有故障峰值移动都在 0.1 % 以内，
   所以已发布的 84.83 A / 255.22 A 不是“1 fF 会改掉”的量。这不等于峰值有硬件精度
   ——见 §5 的模型边界。
3. **两处塌缩不是同一个事件**：基座在 trip 后约 2 ms，变体在 trip 后约 22 µs。
   变体在同一时间片里用了 **3.1 倍**的采样点，说明它在塌缩前就已经在压步长。
   这与 50 V 的“死区 LTE 判据失控”同型，但触发位置不同；根因仍未定位，不猜。

**共同切片的边界**：声明窗口是 5.4–6.0 ms，但变体只到 5.6141 ms，所以工具把两侧
都截到 **5.400–5.614 ms** 再取最大值，并把 `declared_window_fully_covered` 记为
`false`。如果拿基座的 5.4–6.0 ms 去比，多出的 386 µs 只会让基座的最大值单调变大，
差额会变成“覆盖度”而不是物理。`vout_min_after_engage_v` 也因此**不能**与已发布的
全长前缀 −4.98 mV 直接比较——那个下探发生在 6 ms 之后。

**终止方式**：监测器按 raw 尾部时间判定（不是按文件大小）：时间在 5.6140558 ms
停滞超过 6 min、日志里步长警告只差 1e-15 s，确认塌缩后用 `kill <pid>` 结束；
禁止 `taskkill //IM LTspice.exe`。ASCII raw 是流式追加的，所以 5.614 ms 之前的前缀可读。
